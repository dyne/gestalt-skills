# Trees and reusable widgets

For a browser with filters, sorting or multi-selection, keep marks on domain IDs and derive visible rows as in the starter. For an existing termbox-widgets consumer, Clay can supply the bounds of a tree widget directly. The widget supplies a single current node, expansion state, vertical scrolling and a row-draw callback. Its event API permits the application to choose key bindings.

## Embedding termbox-widgets

1. The reviewed `widgets.h` includes **`"termbox.h"`**. Supply a small forwarding header on the include path containing `#include <stdarg.h>` and `#include "termbox2.h"`. Point the latter at libterm's `compat/`, and link libterm. The explicit standard header supplies the variadic declarations that the original header provided transitively.
2. Include the widget header with `WIDGETS_IMPL` in one C file. Provide `stb_ds.h` and compile `STB_DS_IMPLEMENTATION` in a separate file. On POSIX expose `wcwidth` (e.g. `-D_XOPEN_SOURCE=700 -D_DEFAULT_SOURCE`) and choose a UTF-8 locale via `setlocale(LC_CTYPE, "")`. Inspect `widget_uc_sanitize` for its combining-mark treatment before choosing this text painter for international labels.
3. Call `treeview_init`. Create rows with `treeview_node_alloc(payload, draw_row)`. Insert the first row with `TREEVIEW_INSERT_PARENT`, which attaches it to the invisible root and selects it. `TREEVIEW_INSERT` attaches a child to the current node; `TREEVIEW_INSERT_PARENT` adds a sibling. The event result is `WIDGET_REDRAW` or `WIDGET_NOOP`. If insertion fails, destroy the unattached node. Attached nodes are recursively freed by `treeview_finish`; payload ownership belongs to the application.
4. After completing the Clay layout, obtain the tree's content rectangle. In the cell-based layout pass `widget_points_set(&points, x, x + width, y, y + height)`. The parameter order is **x1, x2, y1, y2**, and upper bounds are exclusive. Intersect ancestor clips first and reserve the header outside the widget's rectangle. Call `treeview_redraw(&tree, &points)` before the frame's single present. The callback receives bounds beginning after the branches at the current row; draw only that row.
5. Map navigation to `TREEVIEW_UP`, `TREEVIEW_DOWN`, `TREEVIEW_JUMP` and `TREEVIEW_EXPAND`. EXPAND toggles, so guard it by the existing expansion state for distinct Left/Right semantics. Keep a separate set of marked payload IDs. Have the callback draw both its `is_selected` argument (keyboard cursor) and the membership mark. Drop references to deleted nodes and descendants before the next draw. If routing mouse input, record the callback's visible row→ID mapping for the presented frame.

The upstream `WIDGETS_TESTS` assertion program ran with the forwarding header and libterm in a Linux PTY. A separate tree probe inserted a parent and child, visited both through callbacks inside a bounded pane, navigated down/up and checked that collapsing the parent suppressed the child callback. The widget's MIT notice applies if you redistribute its implementation. [Widget source and license](https://github.com/git-bruh/termbox-widgets/tree/8907de1a4fdd697da3275103c337033d467b180e)

## Other implementations worth reading for a specific task

| Problem | Source and what to examine |
| --- | --- |
| Preserve navigation across folding or scrolling | In ictree, `cursor_set` keeps the active row visible while `fold_path` changes the visible projection. Follow a cursor move and a fold through the path links. [ictree navigation](https://github.com/NikitaIvanovV/ictree/blob/f50002a9a10b8f895bd02f5d5c09179a09a2efaf/src/ictree.c) |
| Split an editor and budget chrome before text | mle's `bview_resize` divides the available rectangle between views, then lays out caption, margins and buffer. Its cursors represent edit positions; row membership for a bulk action is a different model. [mle views](https://github.com/adsr/mle/blob/597052bbd68c366410c590eb8fec482adbe2e875/bview.c) |
| Keep input editing and the renderer from competing for a terminal | The termbox2 readline example installs redisplay/input hooks, suppresses readline's terminal prep and routes input through one owner. Inspect resize handling before embedding it. [readline integration](https://github.com/termbox/termbox2/blob/3a955d360f13f53a6c549d3a3ca3109fc9e8ae7f/demo/readline.c) |
| Diagnose a terminal's actual key encoding | Compare the original keyboard demo with libterm's native event inspector and compatibility editor. Check modifiers, special keys and text separately before choosing bindings. [termbox2 keyboard](https://github.com/termbox/termbox2/blob/3a955d360f13f53a6c549d3a3ca3109fc9e8ae7f/demo/keyboard.c), [libterm examples](https://github.com/rizukirr/libterm/tree/70ea507b2a51a595863cf06e0fb830330c26832b/examples) |
